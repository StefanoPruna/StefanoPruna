System 01 Gameplay

Coral grow system

Players pick up a small piece of coral, place it in the world and watch it grow into a full coral over time. I built it around an extensible item base so every future coral species plugs into the same pipeline.

  • Reusable coral item base shared by all coral types
  • Pickup and placement, on a coral base or freely in the world
  • Growth timer that swaps the small piece for a fully grown one
  • New species need one subclass and one value: their growth duration

System 02 Animation

Swimming and water detection

Retargeting Mixamo animations (Y+ forward) onto our character (X+ forward) worked on land but broke for swimming, where the horizontal body pose compounds the rotation problem. I rebuilt the retargeting pipeline and the water logic around it.

  • Clean IK Rigs and a custom IK Retargeter built from scratch
  • Axis conversion fixed through retarget pose offsets
  • Water detection with Physics Volume overlap checks and hysteresis to stop animation flicker
  • Jump and landing suppressed at the water's edge; natural buoyancy at the surface

System 03 UI

Modular, code driven menu system

Instead of scattering raw buttons and text across every screen, every menu is built from two reusable widget classes and one base menu class, with settings owned by a subsystem.

  • MenuButtonBase and MenuTextBase: styled once, reused everywhere, with live editor preview via NativePreConstruct()
  • BaseMenuWidget handles input mode, cursor, click and hover sounds, and music that persists across menu changes
  • GameSettingsSubsystem, a UWorldSubsystem, owns audio, graphics and gameplay settings

Automated testing

Reachability functional test

Checks automatically that every interactable in a level can physically be reached by the player, before anyone tests it by hand.

  • Four traces per actor, relative to its local rotation, so the test works however a designer places it
  • Fixed intermediate interactables blocking traces to farther targets on large maps
  • Documentation of setup, failure interpretation, known limits and confidence estimates

How I work · 03

Hypothesis, test, then ship

01

Read the source

When documentation runs out, I read Unreal's engine source to get exact signatures and behaviour instead of guessing.

02

Bisect, don't assume

Crashes get isolated systematically: disable half, test, disable a quarter, test, until the real cause is pinned down.

03

Build to extend

Base classes and subsystems so designers and future features plug in without rewriting what exists.

04

Test and document

Automated checks with written limits and confidence levels, so the next person knows what a pass actually means.
